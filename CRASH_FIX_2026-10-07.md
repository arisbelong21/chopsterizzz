# Perbaikan crash Chopster — 7 Oktober 2026 (WIB)

## Penting sebelum dipakai

Paket ini adalah **SOURCE yang diperbaiki**, bukan EXE Windows hasil build baru. ZIP sumber yang tersedia tidak memuat file `.exe`. Mengganti file `.py` di folder source tidak mengubah EXE yang sudah pernah dibangun. Gunakan source ini untuk build ulang di Windows, lalu jalankan hasil build yang baru.

Perbaikan dalam revisi ini terbatas pada enam file Python yang disebutkan di bawah. Fitur, tampilan utama, routing AI, dependensi, aset dan mesin rendering tidak diganti. `AUDIT_FIX_CHOPSTER.md` adalah laporan paket sebelumnya; laporan ini menjelaskan tambahan perbaikan crash saat ini.

## Apa yang menyebabkan error

### 1. `NameError: name 'provider' is not defined`

Lokasi pada log terbaru: `ui/pages/settings_page.py`, callback `done()` yang dipanggil `_on_ai_task_result()`, baris sumber lama 864.

`provider` dan `endpoint` dibuat di dalam fungsi `worker()`, tetapi dipakai oleh fungsi saudara `done()`. Variabel lokal sebuah fungsi tidak otomatis terlihat oleh fungsi saudaranya. Audit menemukan **keduanya** tidak terdefinisi di callback, bukan hanya `provider` yang pertama kali muncul dalam popup.

Perbaikan: baca konfigurasi pada GUI thread sebelum tugas dikirim, simpan nilai untuk worker/callback, dan bangun provider menggunakan nilai yang sama. Empat jalur tes AI tidak lagi membaca widget/config hidup dari worker. Setiap request memiliki ID dan kepemilikan callback; hasil/gagal yang sudah kedaluwarsa setelah setting berubah diabaikan dan tombol milik tugas dipulihkan.

### 2. `RuntimeError: Signal source has been deleted`

Terjadi saat worker mengirim `signals.progress.emit(...)`. Penanganan error kemudian mengirim `signals.failed.emit(...)` melalui sumber yang sama yang sudah dihapus, sehingga muncul error kedua.

Log membuktikan objek pengirim Qt sudah tidak hidup; log saja tidak menetapkan satu pemicu penghapusan yang pasti. Source memiliki kelemahan pengelolaan umur objek dan urutan shutdown/cleanup yang sesuai dengan risiko ini.

Perbaikan: objek sinyal menjadi anak `TaskManager`, pool dimiliki manager, pengiriman callback ke GUI dibuat queued, dan flag pembatalan memakai `threading.Event`. Worker lama dilepas sebelum callback selesai/gagal diberitahukan, agar callback retry tidak kehilangan referensi worker baru. Saat keluar, aplikasi menolak tugas baru, meminta pembatalan, lalu menunggu pool selesai sebelum widget/database dibongkar. Polling dengan QTimer menjaga GUI tetap memproses event selama menunggu. Pembatalan bersifat kooperatif: operasi jaringan/media yang sedang berlangsung dapat memerlukan waktu untuk berhenti.

### 3. `QComboBox already deleted`

Worker analisis memanggil `_preview_target_ratio()` yang membaca dropdown `self.aspect`. Jalur lain membaca input bahasa, subtitle, watermark, project dan media setelah tugas dimulai.

Perbaikan: source path, direktori proyek, rasio, konfigurasi, transcript, parameter ekspor dan nilai widget diambil/disalin **sebelum** worker berjalan. Sebelas fungsi worker Clipper yang diperiksa tidak lagi merujuk `self`. Hasil, error, atau progres dari proyek sebelumnya tidak diterapkan pada proyek baru, termasuk progres scene yang dapat menggerakkan preview.

### 4. Error lama yang juga muncul dalam log gabungan

- `subtitle_overlay` belum ada saat resize: guard inisialisasi sudah ada di source dasar dan dipertahankan; diuji saat widget baru terbentuk sebagian.
- `transcript_prepare_signature` tidak dapat diimpor: kedua fungsi subtitle yang dibutuhkan sudah ada pada source dasar; keberadaannya diperiksa.
- `NameError: border`: kurung CSS dalam f-string tema sudah dibenarkan di source dasar. Fungsi stylesheet dark/light/fallback dijalankan tanpa exception tersebut.
- `RuntimeError: Dibatalkan`: pembatalan sendiri bukan bukti kerusakan transkripsi. Pada log, penanganannya berlanjut ke pengiriman sinyal dari objek yang sudah dihapus; lifecycle di atas menangani jalur itu.

Error-error lama tersebut berasal dari beberapa folder/versi berbeda dalam log; tidak semuanya terjadi dalam satu peluncuran terakhir.

## File yang berubah pada revisi ini

1. `app/task_manager.py` — ownership, queued delivery, cancellation, cleanup/retry, shutdown barrier.
2. `app/application.py` — urutan shutdown sebelum config/database ditutup.
3. `main.py` — kaitkan shutdown dengan `QApplication.aboutToQuit`.
4. `ui/main_window.py` — konfirmasi dan penutupan tertunda saat tugas masih aktif.

## Hasil pengujian

Lingkungan pengujian: sandbox Linux, Python 3.13, PySide6/Shiboken6 **6.11.2**, Qt offscreen. Versi Qt sesuai pin dependensi paket.

- **104 modul Python berhasil dikompilasi**.
- **0 temuan undefined-name/undefined-local** pada pemeriksaan Pyflakes. Ini bukan klaim semua peringatan lint telah dihapus; peringatan kosmetik yang tidak terkait dibiarkan.
- **20 pemeriksaan lifecycle lulus**: 40 QRunnable, 400 update progres, GC, thread GUI, cleanup sinyal, tugas duplikat, pembatalan antrean/berjalan, retry langsung, lima kali resubmit dari callback, shutdown, penutupan yang ditolak/disetujui, respons timer GUI, serta database ditutup sesudah worker.
- **87 pemeriksaan Settings lulus**: dua provider, empat jalur worker, 56 skenario hasil/error kedaluwarsa, duplikat, cleanup callback, tombol, penolakan submit dan auto-discovery.
- **26 pemeriksaan Clipper/komponen lulus**: audit sebelas worker tanpa referensi halaman, worker master/subtitle berjalan setelah objek Qt halaman benar-benar dihapus, snapshot tetap memakai proyek/nilai awal, hasil/progres/error lama diabaikan, guard preview, stylesheet, dan simbol subtitle.
- Total **133 pemeriksaan komponen/regresi**. Ini bukan 133 pengujian end-to-end aplikasi.
- ZIP kode lulus pemeriksaan CRC sebelum laporan ini ditambahkan; integritas paket final diperiksa pada langkah penyerahan.

Tes memakai Qt asli, tetapi provider AI, backend media dan beberapa objek aplikasi menggunakan test double. Salah satu harness gabungan Settings sempat segfault setelah pemeriksaan awal; kasus queued-delivery kemudian dipisah dengan umur widget uji yang dijaga. Harness utama 87 pemeriksaan berhasil diulang oleh sesi utama dengan exit code 0. Tidak ada klaim bahwa kegagalan harness tersebut membuktikan aplikasi lengkap sudah diuji.

### Yang belum diverifikasi

EXE Windows final, GPU/CUDA, semua codec/FFmpeg, koneksi API/key milik pengguna, transkripsi video nyata, dan ekspor end-to-end pada komputer pengguna **belum diuji di sini**. Tidak ada jaminan universal "nol error" untuk semua mesin/input. Yang terverifikasi adalah perbaikan source dan pengujian di atas.

## Cara membuat dan menjalankan EXE baru

1. Tutup Chopster lama. Simpan proyek penting; jangan hapus data aplikasi.
2. Ekstrak ZIP ke **folder baru**, bukan menimpa folder build lama.
3. Buka folder `chopster` hasil ekstraksi dan jalankan `build_exe.bat` di Windows. Script build yang sudah tersedia memakai `PyInstaller --clean`.
4. Setelah build menyatakan berhasil, jalankan **`dist\Chopster\Chopster.exe` dari folder hasil build baru**. Jangan memakai shortcut/EXE lama.
5. Jika memindahkan hasil build, pindahkan seluruh folder `dist\Chopster`, termasuk `_internal`; jangan hanya menyalin EXE-nya.
6. Uji Settings → tes koneksi/vision, lalu satu video singkat → transkripsi → analisis/scene → subtitle → ekspor. Coba pembatalan, pergantian proyek, dan keluar ketika tugas aktif.

## Membaca log yang benar

`app/crash_guard.py` membuka `crash.log` dalam mode append. Baris `===== Chopster crash guard started =====` hanya penanda peluncuran crash guard, **bukan error**. Perhatikan blok `[UNHANDLED]` berikutnya.

Lokasi normal Windows dari source: `%APPDATA%\ChopsterByAris\logs\crash.log`; jika lokasi data tidak tersedia, kode memakai folder `logs` di working directory. Untuk membedakan pengujian baru, sesudah aplikasi ditutup, simpan/rename log lama sebagai arsip sebelum menjalankan build baru. Jangan menghapus seluruh folder data/config/proyek.
